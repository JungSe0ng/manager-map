# 매니저 관계도 (Manager Map)

Unity 프로젝트의 매니저 클래스, 함수, 매니저 간 관계를 팀이 함께 편집하는 웹 도구입니다.
데이터는 Firebase Firestore에 실시간으로 저장되고, 구글 로그인으로 허용된 팀원만 접근할 수 있습니다.

## 처음 설정 (한 번만)

### 1. Firebase 프로젝트 만들기
1. https://console.firebase.google.com 에서 **프로젝트 추가** (Google 애널리틱스는 꺼도 됩니다)
2. 왼쪽 **빌드 > Authentication > 시작하기 > Sign-in method**에서 **Google** 사용 설정
3. **빌드 > Firestore Database > 데이터베이스 만들기** (위치: `asia-northeast3 (서울)`, **프로덕션 모드**)

### 2. 보안 규칙 적용
1. 이 저장소의 `firestore.rules` 내용을 복사
2. `YOUR_EMAIL@gmail.com`을 **관리자 본인의 구글 이메일(소문자)** 로 바꿈
3. Firestore Database > **규칙** 탭에 붙여넣고 **게시**

### 3. 웹 앱 등록
1. 프로젝트 설정(톱니바퀴) > **내 앱 > 웹(</>)** 으로 앱 등록 (Hosting 체크는 안 해도 됨)
2. 표시되는 `firebaseConfig` 값을 `config.js`에 넣고 커밋

### 4. 승인 도메인 추가
Authentication > **설정 > 승인된 도메인**에 GitHub Pages 주소의 도메인(예: `<사용자명>.github.io`)을 추가

### 5. 첫 로그인
사이트를 열고 관리자 계정으로 로그인하면 자동으로 관리자로 등록됩니다.
상단 **팀원 관리**에서 팀원의 구글 이메일을 추가하세요.

## 기존 데이터 옮기기
로그인 → 오른쪽 위 **내보내기 > 가져오기**에서 JSON 파일(`initial-data.json` 등)을 선택하면 지금 페이지로 들어갑니다.

## 규칙 업데이트 (페이지·게임·히스토리 기능 추가 후)
이전 버전의 `firestore.rules`를 쓰고 있었다면, 새 `firestore.rules` 전체를 Firestore Database > **규칙** 탭에 다시 붙여넣고 **게시**하세요.
- `boards` 부분이 없으면 새 페이지를 만들 수 없어요.
- `games` 부분이 없으면 새 게임을 만들 수 없어요. (사이트에 "Firestore 규칙에 games 부분이 없어요"라고 표시됩니다)
- `history` 부분이 없으면 편집 히스토리가 쌓이지 않아요. 편집 자체는 저장됩니다. (히스토리 칸에 안내가 표시됩니다)

## 데이터 구조
기존 데이터는 옮기지 않고 그대로 **첫 번째 게임**이 됩니다. 새로 만든 게임만 `games/` 아래에 저장돼요.

| 대상 | 첫 번째 게임 | 추가한 게임 |
| --- | --- | --- |
| 게임 이름 | `meta/project` | `games/{게임ID}` |
| 페이지 목록 | `boards/{페이지ID}` | `games/{게임ID}/boards/{페이지ID}` |
| 기본 페이지 데이터 | `managers`, `links` | `games/{게임ID}/boards/main/managers`, `links` |
| 추가 페이지 데이터 | `boards/{페이지ID}/managers`, `links` | `games/{게임ID}/boards/{페이지ID}/managers`, `links` |
| 편집 히스토리 | 기본 페이지 `history`, 추가 페이지 `boards/{페이지ID}/history` | `games/{게임ID}/boards/{페이지ID}/history` |

매니저 문서의 `px, py`는 자유 배치 위치(없으면 자동 배치), `ref: {g, b, id}`는 참조 카드가 가리키는 원본(게임·페이지·매니저 ID)입니다.

## 기능
- 매니저 등록, 분류, 역할 설명
- 함수: 종류(메서드/이벤트/프로퍼티), Public/Internal, 그룹, ★핵심
- 카드 표시: 축소하면 이름만, 평소엔 요약. 도구막대 **함수 전체** 토글로 Public 함수 전체, **★핵심만** 토글로 ★ 함수만 (함수 표에도 적용)
- 함수 단위 관계 연결 (호출·참조·이벤트 구독·소유). 관계선은 언리얼 블루프린트처럼 카드 옆면에서 대상 함수 줄로 이어짐
- 관계선 종류 필터: 아래 범례의 호출·참조·이벤트 구독을 눌러 그 종류만 보기 (여러 개 선택 가능)
- 자유 배치: 카드를 끌어 원하는 곳에 두기. **Shift**를 누른 채 다른 카드에 놓으면 하위로, 빈 곳에 놓으면 독립 매니저로
- 자동 정리: 상위·하위는 유지하고 관계선이 덜 꼬이도록 카드를 다시 배치 (히스토리로 되돌리기 가능)
- 다른 페이지 매니저 참조: 다이어그램에서 **Space**(또는 ↗ 불러오기) → 모든 게임·페이지에서 이름 검색 → 커서 위치에 참조 카드로 배치. 원본이 바뀌면 자동 반영되고, 내용 편집은 **원본 열기**로 원본 페이지에서
- Unity C# 코드 붙여넣기로 함수 일괄 등록 (`///` 주석 → 설명, `#region` → 그룹)
- 함수 표 보기: 검색, 정렬, "사용처 없는 Public" 필터
- 게임 여러 개: 제목 옆 **게임 목록 ▾**에서 전환·새 게임·삭제, 제목을 눌러 게임 이름 변경 (첫 번째 게임은 삭제 불가)
- 게임마다 페이지 여러 개: 탭으로 전환, 새 페이지·이름 변경·복제·삭제
- 편집 히스토리: 오른쪽 아래에 페이지별로 팀 전체의 편집(추가·수정·삭제·관계·이동)이 작성자·시간과 함께 쌓이고, 항목을 눌러 **이 시점으로 되돌리기** 가능 (되돌린 것도 기록으로 남아 다시 되돌릴 수 있음, 페이지당 최근 100개)
- 링크 공유: 첫 번째 게임은 `#b-페이지ID`, 추가한 게임은 `#g-게임ID` / `#g-게임ID/b-페이지ID`
- 내보내기: PNG 이미지(카드 내용·관계선·해상도 선택), 함수/관계 목록 CSV, Markdown 문서, JSON 백업(이 페이지/이 게임 전체)

## 비용
Firebase 무료(Spark) 플랜으로 소규모 팀은 충분합니다. (Firestore 무료 한도: 하루 읽기 5만, 쓰기 2만 회)
